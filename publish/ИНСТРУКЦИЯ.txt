║          ConSecOrg — Инструкция по запуску               ║
╚══════════════════════════════════════════════════════════╝

Что нужно установить заранее
──────────────────────────────
1. Microsoft SQL Server (любой выпуск: Developer, Express, Standard)
   Скачать бесплатно: https://www.microsoft.com/ru-ru/sql-server/sql-server-downloads

2. SQL Server Management Studio (необязательно, но удобно)
   Скачать: https://aka.ms/ssmsfullsetup


═══════════════════════════════════════════════════════════
 ШАГ 1 — Настроить подключение к базе данных
═══════════════════════════════════════════════════════════

Открой файл:  Server\appsettings.json  (любым блокнотом)

Найди строку:
  "DefaultConnection": "Server=RAMPA;Database=ConSecOrg;..."

Замени  RAMPA  на имя своего SQL Server.

Как узнать имя сервера:
  - Открой SQL Server Management Studio
  - Имя сервера будет в поле "Имя сервера" при подключении
  - Обычно это:  localhost  или  .\SQLEXPRESS  или  имя_компьютера

Примеры:
  "Server=localhost;Database=ConSecOrg;..."
  "Server=.\SQLEXPRESS;Database=ConSecOrg;..."
  "Server=MYPC\SQLEXPRESS;Database=ConSecOrg;..."

Сохрани файл.


═══════════════════════════════════════════════════════════
 ШАГ 2 — Запустить сервер
═══════════════════════════════════════════════════════════

Запусти файл:  start-server.bat

При первом запуске сервер автоматически:
  - Создаст базу данных ConSecOrg
  - Создаст все таблицы
  - Добавит 4 роли (Admin, Manager, Auditor, User)
  - Сгенерирует JWT-секрет

Сервер запустится на:  http://localhost:5205
Swagger (документация API):  http://localhost:5205/swagger

Окно консоли должно оставаться открытым — это и есть сервер.


═══════════════════════════════════════════════════════════
 ШАГ 3 — Создать администратора
═══════════════════════════════════════════════════════════

Пока сервер работает, запусти:  create-admin.bat

Будет создан первый администратор:
  Логин:   admin
  Пароль:  Admin1234!@#$

Или создай пользователя через Swagger вручную:
  1. Открой http://localhost:5205/swagger
  2. POST /api/v1/auth/bootstrap
  3. Тело запроса:
     {
       "username": "admin",
       "email": "admin@company.ru",
       "password": "Admin1234!@#$"
     }

  ⚠ Если bootstrap возвращает 409 — пользователи уже существуют.

──────────────────────────────────────────────────────────
Выдать права Admin существующему пользователю через SQL:
──────────────────────────────────────────────────────────

  Открой SQL Server Management Studio, подключись к серверу,
  открой New Query и выполни:

  -- Посмотреть список пользователей и их роли
  SELECT u.username, r.name AS role
  FROM users u JOIN roles r ON u.role_id = r.id;

  -- Выдать роль Admin пользователю (замени 'username' на нужный логин)
  UPDATE users
  SET role_id = (SELECT id FROM roles WHERE name = 'Admin')
  WHERE username = 'username';


═══════════════════════════════════════════════════════════
 ШАГ 4 — Запустить клиент и подключиться
═══════════════════════════════════════════════════════════

Запусти файл:  Client\start-client.bat   (или Client\ConSecOrg.Client.exe)

На экране выбора режима выбери:  Корпоративный

В поле URL сервера введи:
  http://localhost:5205          ← если клиент на том же компьютере что и сервер
  http://192.168.x.x:5205       ← если клиент на другом компьютере в сети

Нажми Подключиться → Войти с логином admin и паролем Admin1234!@#$


═══════════════════════════════════════════════════════════
 ШАГ 5 — Персональный режим (без сервера)
═══════════════════════════════════════════════════════════

Если нужен персональный режим (без сервера, данные хранятся локально):

  1. Запусти Client\ConSecOrg.Client.exe
  2. Выбери:  Персональный режим
  3. Придумай PIN-код (минимум 4 цифры) — он защищает локальные данные
  4. Готово. SQL Server и сервер не нужны.

  ⚠ Данные хранятся в базе на твоём компьютере.
    При переустановке Windows данные нужно предварительно экспортировать.


═══════════════════════════════════════════════════════════
 Если что-то не работает
═══════════════════════════════════════════════════════════

Сервер не запускается:
  → Проверь что SQL Server запущен (Диспетчер задач → Службы → SQL Server)
  → Проверь имя сервера в appsettings.json
  → Посмотри текст ошибки в окне консоли

"Доступ запрещён" / 401 в клиенте:
  → Убедись что сервер запущен (start-server.bat должен быть открыт)
  → Проверь URL в поле подключения: http://адрес_сервера:5205

Клиент не подключается с другого компьютера:
  → На компьютере с сервером открой порт в брандмауэре:
    Пуск → Брандмауэр Windows → Входящие правила → Создать правило
    Тип: Порт → TCP → 5205 → Разрешить подключение
  → В URL клиента используй IP-адрес сервера, не localhost
